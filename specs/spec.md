# spec.md — Specify (вариант 18)

> Статус: **draft v0.1**, ожидает human-gate (рецензия преподавателя). Источник истины для plan/tasks.

## 1. Назначение
ИАС «Качество обработки обращений в call-центр» банка «N» на основе сведений ИС «Мониторинг реализации основных бизнес-процессов» и во взаимодействии с ИС «Голосовой помощник банка “N”» создаёт сценарии оптимальной обработки обращений и контролирует соответствие действий операторов и сотрудников этим сценариям. Оцениваются только звонки с участием оператора/специалистов.

## 2. Роли
- Оператор call-центра — объект оценки; видит свои утверждённые оценки.
- Аналитик аналитического отдела ДКК — группы обращений, сценарии, отчёты.
- Аудитор — оценивает и утверждает соответствие сценарию.
- Клиент банка — называет тему помощнику, отвечает «решён/не решён».
- ИИ-агент — компонент системы, только предлагает.

## 3. Пользовательские истории
- US1. Как аналитик, я веду группы обращений и сценарии с ≥5 параметрами, чтобы было с чем сравнивать звонки.
- US2. Как аудитор, я вижу карточку звонка с числами и качественными пометками, чтобы решить, соответствует ли порядок действий сценарию.
- US3. Как аудитор, я вижу, где сменилась тема или было несколько вопросов, чтобы не наказывать оператора за обоснованное отклонение.
- US4. Как аналитик, я вижу KPI по группам и периодам, чтобы пересматривать сценарии.

## 6. EARS-требования и критерии приёмки

**E01 (Ubiquitous)** — Система «Качество обработки обращений в call-центр» должна относить каждый оцениваемый звонок ровно к одной основной группе обращений или к категории «иное».  
*Приёмка:* На тестовом наборе из N звонков [предложение автора] каждый звонок имеет ровно одну основную группу; звонков без группы — 0.  
*Трассировка:* FR-03, FR-06; UC «Сегментировать обращение»; Act TO-BE «Отнести к группе» → Модуль сегментации / справочник групп

**E02 (Ubiquitous)** — Система должна хранить для каждой группы обращений сценарий оптимальной обработки, содержащий не менее пяти параметров соответствия, и номер версии сценария.  
*Приёмка:* Попытка сохранить сценарий с <5 параметрами отклоняется; у каждого опубликованного сценария есть версия.  
*Трассировка:* FR-04; UC «Вести сценарии» → Реестр сценариев (версионируемое хранилище)

**E03 (Ubiquitous)** — Система должна показывать аудитору каждую ИИ-оценку вместе с объяснением и ссылками на фрагменты транскрипта.  
*Приёмка:* 100 % ИИ-оценок P01/P02/P06 на экране имеют объяснение и ≥1 ссылку на фрагмент; без них оценка помечена «нет обоснования» и не предлагается к утверждению.  
*Трассировка:* FR-10, FR-11; UC «Оценить звонок»; Seq аудитор–система–агент → UI аудитора; сервис объяснений

**E04 (Event-driven)** — Когда из ИС «Мониторинг…» поступает завершённый звонок с участием оператора, система должна создать карточку оценки с темой, названной голосовому помощнику, и событиями звонка.  
*Приёмка:* Для каждого импортированного звонка с оператором создана карточка; поля темы и событий заполнены или помечены «нет данных».  
*Трассировка:* FR-01; Act TO-BE «Получить данные звонка» → Адаптер ИС «Мониторинг…» (будущий MCP-сервер, только чтение)

**E05 (Event-driven)** — Когда звонок завершён без соединения с оператором или специалистом, система должна исключить его из оценки качества.  
*Приёмка:* На тестовом наборе диалоги только с помощником не попадают в очередь аудитора (0 шт.).  
*Трассировка:* FR-02; Act TO-BE шлюз «Был оператор?» → Фильтр загрузки

**E06 (Event-driven)** — Когда клиент сообщил голосовому помощнику результат «вопрос решён / не решён», система должна записать его в параметр P05 карточки звонка.  
*Приёмка:* Значение P05 в карточке совпадает с данными ИС «Голосовой помощник» для 100 % проверяемых звонков; при отсутствии ответа — «нет ответа».  
*Трассировка:* FR-09; Act AS-IS «Опрос клиента»; TO-BE «Учесть фидбек» → Адаптер ИС «Голосовой помощник» (только чтение)

**E07 (Event-driven)** — Когда ИИ-агент обнаруживает в транскрипте смену темы или дополнительный вопрос, система должна добавить в карточку новую тему с отметкой времени и предложить аудитору сценарий для неё.  
*Приёмка:* На размеченной выборке с многотемными звонками доля найденных смен темы ≥ порога [предложение автора]; каждая найденная тема имеет таймстемп.  
*Трассировка:* FR-07; Act TO-BE «Выявить смену темы»; State «Тема звонка» → ИИ-агент (анализ транскрипта)

**E08 (Event-driven)** — Когда аудитор утверждает или изменяет оценку, система должна зафиксировать итог, автора, время и исходное предложение ИИ.  
*Приёмка:* В журнале для каждого решения есть: предложение ИИ, итог, ID аудитора, время; изменённые оценки отличимы от утверждённых без правок.  
*Трассировка:* FR-12; Seq «Утвердить оценку» → Журнал решений / аудит-лог

**E09 (State-driven)** — Пока сценарий находится в статусе «черновик», система не должна применять его к оценке звонков.  
*Приёмка:* Звонки, поступившие при черновом сценарии, оцениваются по последней опубликованной версии или помечаются «иное / нет сценария».  
*Трассировка:* FR-04, FR-05; State «Сценарий» → Реестр сценариев: жизненный цикл

**E10 (State-driven)** — Пока ИИ-компонент находится в режиме деградации, система должна оценивать звонки только детерминированными правилами (тема помощника, P03, P04, P05) и помечать P01, P02, P06 как «требует ручной оценки».  
*Приёмка:* При отключённом агенте карточки создаются, P03–P05 рассчитаны, P01/P02/P06 помечены; ошибок обработки нет.  
*Трассировка:* FR-13; Act TO-BE ветка «Агент недоступен» → Rule engine (fallback)

**E11 (State-driven)** — Пока оценка звонка не утверждена аудитором, система должна показывать её как «предложение» и не включать в отчёты по операторам.  
*Приёмка:* Неутверждённые оценки отсутствуют в отчётах FR-14; на экране имеют статус «предложение».  
*Трассировка:* FR-11, FR-14; State «Оценка звонка» → Сервис отчётности; статусная модель

**E12 (Optional)** — Где включена функция анализа тональности, система должна показывать P06 как вспомогательный признак с фрагментами текста и без влияния на итог соответствия.  
*Приёмка:* При включённой функции P06 виден с фрагментами; при выключенной — отсутствует; итог соответствия в обоих случаях одинаков при равных P01–P05.  
*Трассировка:* FR-10; UC «Оценить звонок» (extend) → Флаг конфигурации; ИИ-агент

**E13 (Optional)** — Где для группы обращений задан ориентир длительности или числа переключений, система должна показывать аудитору отклонение P03/P04 от ориентира.  
*Приёмка:* Для групп с ориентиром отображается отклонение (абс. и %), для групп без ориентира — «ориентир не задан».  
*Трассировка:* FR-08; Act TO-BE «Рассчитать параметры» → Модуль расчёта метрик

**E14 (Unwanted behaviour)** — Если тема, названная голосовому помощнику, не соответствует ни одной группе обращений, то система должна отнести звонок к категории «иное» и направить его аудитору на ручной разбор.  
*Приёмка:* Звонки с нераспознанной темой получают «иное» и попадают в очередь ручного разбора; доля потерянных — 0.  
*Трассировка:* FR-06; Act TO-BE шлюз «Группа найдена?» → Модуль сегментации

**E15 (Unwanted behaviour)** — Если ИИ-агент возвращает ответ не по схеме, с уверенностью ниже порога или без ссылок на транскрипт, то система должна отклонить предложение агента, записать событие в журнал и перевести карточку на детерминированную оценку.  
*Приёмка:* Инъекция некорректного ответа в тесте → предложение отклонено, событие в журнале, карточка в режиме fallback.  
*Трассировка:* FR-10, FR-13; Act TO-BE «Проверить ответ агента» → Валидатор схемы ответа; журнал tool-calls

## 9. Допущения
- Параметры соответствия P01–P06 и их шкалы — предложение автора (в методичке не перечислены).
- Наличие транскриптов разговоров, таймстемпов и детализации событий телефонии (соединения, переводы) — допущение; методичкой не подтверждено.
- Распределение: аналитик готовит сценарии, аудитор согласует публикацию — предложение автора.
- Пороги точности ИИ, размер выборки, периодичность мониторинга — предложения автора; числовые нормативы банка не выдумываются.
- Тональность — только по тексту, вспомогательный признак, отключаемый (Optional).
- Явный фидбек P05 — существующий опрос голосовым помощником, новый канал не вводится.
- Срок сдачи этапа 1 — 16.11.2026 со слов студентки; в тексте задания даты нет.
